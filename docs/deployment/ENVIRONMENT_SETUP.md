# Multi-Environment Secrets & Variables Configuration

To support a secure, enterprise-grade multi-environment CI/CD pipeline, the configuration is split into two layers:
1. **GitHub Settings (Environments)**: Controls build, docker pushes, and Cloud Run targeting.
2. **GCP Secret Manager**: Securely stores sensitive database, cache, and application credentials that are injected into your FastAPI container at runtime.

---

## 🔑 1. GCP Secret Manager (Stored in GCP)
These sensitive secrets must be created in Google Cloud Secret Manager. 
If you are using **one GCP Project per Environment** (recommended), create them under each project using these exact names. If you are using a single project, you can suffix them and update the `deploy.yml` secrets mapping.

| Secret ID / Name | Description | Example Value |
|:---|:---|:---|
| `DATABASE_URL` | Async connection string for Cloud SQL (PostgreSQL). *Note: For Cloud Run, use the Unix socket path.* | `postgresql+asyncpg://fastapi_user:superpassword@/fastapi_db?host=/cloudsql/PROJECT_ID:REGION:INSTANCE_NAME` |
| `REDIS_URL` | TLS-enabled Redis connection string (Redis Cloud). | `rediss://default:strongpassword@redis-12345.ec2.cloud.redislabs.com:12345` |
| `JWT_SECRET_KEY` | Symmetric secret key for signing JWT tokens. | *Run `openssl rand -hex 32` to generate (e.g., `cb283b32...`)* |

> [!IMPORTANT]
> The Cloud Run service account must have the **Secret Manager Secret Accessor** (`roles/secretmanager.secretAccessor`) role granted to access these secrets. This is handled automatically by the `setup-gcp.sh` and `setup-cloudsql.sh` scripts.

## 🐙 2. GitHub Actions Secrets & Variables (Stored in GitHub)
Configure these under **Settings -> Environments** inside your GitHub repository for the `development`, `staging`, and `production` environments:

### A. Environment Secrets (Sensitive - masked in build logs)
| Secret Name | Description | Source / How to Obtain |
|:---|:---|:---|
| `GCP_PROJECT_ID` | The Google Cloud Project ID for the environment. | e.g., `my-project-dev` |
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | Full resource name of the OIDC provider. | Generated by `scripts/gcp/setup-gcp.sh` |
| `GCP_SERVICE_ACCOUNT` | Email of the deployer Service Account. | Generated by `scripts/gcp/setup-gcp.sh` |

### B. Environment Variables (Non-sensitive - visible in build logs)
| Variable Name | Description | Example Value |
|:---|:---|:---|
| `GCP_REGION` | Target deployment region. | `asia-south1` |
| `GCP_ARTIFACT_REPO` | Docker registry repository name. | `fastapi-app` |
| `GCP_SERVICE_NAME` | Cloud Run service name. | `fastapi-dev` (development) <br> `fastapi-stage` (staging) <br> `fastapi-prod` (production) |
| `CLOUD_SQL_INSTANCE` | The fully qualified connection string of the SQL instance. | `project-id:region:instance-name` |
| `GCS_PUBLIC_BUCKET` | Dedicated public bucket for the environment. | `my-project-public-dev` |
| `GCS_PRIVATE_BUCKET` | Dedicated private bucket for the environment. | `my-project-private-dev` |

## 🛠️ Step-by-Step Configuration Flow
1. **Provision GCP Resources**: Run the `scripts/gcp/setup-gcp.sh` and `scripts/database/setup-cloudsql.sh` scripts.
2. **Create Secrets in Secret Manager**: Navigate to **GCP Console -> Security -> Secret Manager** and create `DATABASE_URL`, `REDIS_URL`, and `JWT_SECRET_KEY`.
3. **Configure GitHub**: Create `development`, `staging`, and `production` Environments in GitHub, and enter the respective secrets and variables matching the tables above.
4. **Deploy**: Push/Merge your branch to trigger the pipeline (`develop` -> Development, `stage` -> Staging, `main` -> Production).
